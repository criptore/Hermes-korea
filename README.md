# HERMES

A **100% local** desktop application that watches public tender portals and drafts
responses automatically. No cloud, no recurring cost, and mandatory human approval
before anything is submitted.

Runs on **Windows 10/11** and **macOS 11+** (Apple Silicon and Intel).

## Architecture

| Component | Technology | Role |
|-----------|------------|------|
| **HERMES** | Tauri 2 + React 18 + Tailwind | Desktop app, orchestrator |
| **ARGOS** | Playwright + APScheduler | Collects / scrapes tender portals |
| **KRINOS** | PyMuPDF (+ pdfplumber fallback) + RapidOCR ONNX + Ollama + Laya judge (ONNX) | Extraction, analysis, scoring |
| **HERMION** | Ollama + workflow engine | Drafts responses |
| **MNEMOSYNE** | SQLite + SQLModel | Local database |
| **PYTHIA** | Ollama + Qwen3 8B | Local LLM |

The FastAPI backend listens on `127.0.0.1:8000` only — no port is ever exposed
outside the machine.

### Language

The interface, API messages and agent logs are in **English**. Text generated by
PYTHIA (KRINOS summaries, HERMION drafts, workflows) is in English by default and
can be switched with `HERMES_PYTHIA_LANGUE_SORTIE` (e.g. `French`, `Korean`).
Watch keywords must match the language of the collected notices
(`HERMES_LANGUE_PORTAILS`, default `French` for BOAMP/TED France). Code
identifiers, API routes and the MNEMOSYNE schema are unchanged, so existing
databases keep working.

## Installation (end users)

### Windows

> Windows 10/11 64-bit. No prerequisites: no Python, Node, Rust or Ollama to
> install — the installer takes care of everything.

1. **Download** the latest installer from the repository's Releases page:
   `HERMES-Setup-<version>.exe` (**~800 MB**, Ollama bundled).
2. **Double-click** it → guided install → desktop shortcut and Start menu entry.
3. **Start HERMES.** On first launch, the app offers to download the Qwen3 8B
   language model (**~5.2 GB**, progress bar). This needs an internet connection
   **once**; afterwards HERMES runs fully offline.

User data lives in `%LocalAppData%\HERMES` (SQLite database, documents, logs,
local master key, Ollama models downloaded by HERMES). On uninstall you can keep
or delete it.

### macOS

> macOS 11 Big Sur or later. Full guide: [`docs/macos.md`](docs/macos.md).

1. **Install Ollama** (PYTHIA's engine): download the app from
   <https://ollama.com/download> and move it to *Applications*
   (or `brew install ollama`).
2. **Download** `HERMES-<version>-macos-<arch>.dmg` (`arm64` for Apple Silicon,
   `x86_64` for Intel), open it and drag **HERMES** onto **Applications**.
3. **First launch:** the build is ad-hoc signed (not notarised), so macOS blocks
   the first opening. Right-click HERMES → *Open*, or on macOS 15+ go to
   *System Settings → Privacy & Security → Open Anyway*. Command-line
   alternative: `xattr -dr com.apple.quarantine /Applications/HERMES.app`.
4. HERMES starts Ollama if needed (or reuses the running Ollama app), starts its
   bundled backend, then offers to download the model.

User data lives in `~/Library/Application Support/HERMES`. Models stay in
Ollama's default folder (`~/.ollama/models`), shared with the Ollama app.

On both platforms, closing HERMES stops the backend and any Ollama instance it
started; an Ollama that was already running is left alone.

- **git**

- Ollama/PYTHIA runs locally on `127.0.0.1:11434`.

  `D:\HermesDeps\ollama`. Heavy HERMES downloads stay on `D:` when the tool
  allows it (`HERMES_DEPS_DIR` or `-DepsRoot <path>` to use another drive).

## Running HERMES (dev)

### Local ports

| Port | Service | Role |
|------|---------|------|
| `8000` | HERMES FastAPI backend | Local API (`/health`, `/appels-offre`, `/hermion`, …) |
| `5173` | Vite React frontend | Web dev interface |
| `11434` | Ollama / PYTHIA | Local LLM used by KRINOS and HERMION |

These ports must stay bound to `127.0.0.1` and never be exposed on the network.

### macOS / Linux

```bash
./scripts/setup-macos.sh        # checks prerequisites, venv, npm ci (once)
./scripts/start-pythia.sh       # PYTHIA / Ollama (reuses the Ollama app if running)
./scripts/start-backend.sh      # FastAPI on 127.0.0.1:8000 (hot reload)
./scripts/start-desktop.sh      # Tauri window — or: cd frontend && npm run dev
./scripts/kill-hermes.sh        # stop leftover HERMES processes (--ollama to include Ollama)
./scripts/build-macos.sh        # HERMES.app + DMG in installer/dist/
./scripts/sync-version.sh 1.0.2 # bump the version everywhere (--check to verify)
```

### Windows (PowerShell 7)

```powershell
.\scripts\start-pythia.ps1     # starts Ollama/PYTHIA from D:
.\scripts\start-backend.ps1    # starts FastAPI with the HERMES paths
.\scripts\start-desktop.ps1    # Tauri dev with caches on D:
.\scripts\start-hermes.ps1     # everything + cleanup when the window closes
.\scripts\kill-hermes.ps1      # kill zombie HERMES processes
.\scripts\build-backend.ps1    # standalone backend.exe (PyInstaller)
.\scripts\build-installer.ps1  # HERMES-Setup-<version>.exe (Inno Setup)
.\scripts\sync-version.ps1 X.Y.Z  # bump the version everywhere (-Check to verify)
```

### Manual steps

```bash
cd backend
python3.12 -m venv .venv            # Windows: py -3.12 -m venv .venv
source .venv/bin/activate           # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn hermes.main:app --reload --host 127.0.0.1 --port 8000
pytest

cd ../frontend
npm install
npm run dev          # http://127.0.0.1:5173
npm run tauri dev    # desktop window (requires Rust)
```

Checks: <http://127.0.0.1:8000/health> → `{"status":"ok",...}`,
<http://127.0.0.1:8000/docs> → Swagger UI.

In debug builds (`tauri dev`) the desktop app starts nothing: run the backend and
PYTHIA yourself. Release builds own the whole lifecycle (see below).

## Desktop lifecycle and packaging

In release, the Tauri app starts PYTHIA (if not already running) and the backend
as child processes, emits their state to the UI, and stops them when HERMES quits.
If the app is killed abruptly, Windows uses a “kill-on-close” Job Object; on
macOS/Linux the backend receives `HERMES_PARENT_PID` and shuts itself (and the
Ollama HERMES started) down when the app disappears.

Backend lookup order: `HERMES_BACKEND_EXE`, then `backend/backend(.exe)` next to
the executable (Windows installer), then `HERMES.app/Contents/Resources/backend/`
(macOS bundle), then the repository's Python venv (dev fallback). Other overrides:
`HERMES_OLLAMA_EXE`, `HERMES_DATA_DIR`, `OLLAMA_MODELS`.

### Windows installer (Inno Setup)

`scripts/build-installer.ps1` runs the full chain: `npm run tauri build` →
`hermes.exe`, `scripts/build-backend.ps1` → `backend\backend.exe` (~115 MB,
no external Python needed), downloads `OllamaSetup.exe`, then compiles with
`ISCC.exe`. Output: `installer/dist/HERMES-Setup-<version>.exe`. Options
(`-SkipFrontend`, `-SkipBackend`, `-SkipOllama`) in
[`installer/README.md`](installer/README.md).

### macOS app and DMG

`scripts/build-macos.sh` builds the PyInstaller backend, the Tauri app, embeds the
backend in `HERMES.app/Contents/Resources/backend`, signs the bundle (ad-hoc by
default, Developer ID with `APPLE_SIGNING_IDENTITY`) and produces
`installer/dist/HERMES-<version>-macos-<arch>.dmg`. `scripts/smoke-macos.sh`
checks that the app starts its bundled backend and that the backend stops when
the app dies. The *macOS bundle* GitHub workflow runs both on every relevant
change and publishes the DMG as an artifact. Details, signing and notarisation:
[`docs/macos.md`](docs/macos.md).

## PYTHIA: LLM engines and model benchmark

PYTHIA supports two engines, both **strictly local** (the URL must be
`127.0.0.1`, `localhost` or `::1`, otherwise the call is refused):

| Variable | Value | Role |
|---|---|---|
| `HERMES_PYTHIA_MOTEUR` | `ollama` (default) or `openai_compatible` | Inference engine |
| `HERMES_OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Ollama URL (`ollama` engine) |
| `HERMES_PYTHIA_URL` | `http://127.0.0.1:8080/v1` | Base URL of a `/v1/chat/completions` server (llama.cpp `llama-server`, LM Studio, vLLM…) |
| `HERMES_PYTHIA_MODELE` | `qwen3:8b` | Model name on the engine |
| `HERMES_PYTHIA_LANGUE_SORTIE` | `English` | Language of generated text |
| `HERMES_LANGUE_PORTAILS` | `French` | Language of collected notices (filter keywords) |

The `openai_compatible` engine sends KRINOS structured outputs through
`response_format` (`json_schema`). The model context is set when the server starts
(`llama-server -c 16384`), not by HERMES. With Ollama's `/v1` (local testing),
Ollama applies its own default: start it with `OLLAMA_CONTEXT_LENGTH=16384`,
otherwise KRINOS prompts (~5k tokens) are truncated.

**Hugging Face models (GGUF) through Ollama**: `hf.co/<org>/<repo>:<quant>` is a
valid model name, e.g. `HERMES_PYTHIA_MODELE=hf.co/unsloth/Qwen3-8B-GGUF:Q4_K_M`.

### Comparing models (benchmark)

`backend/scripts/banc_pythia.py` runs KRINOS on fictitious reference tenders
(`backend/scripts/banc_fixtures/*.json`, with expectations: score range, tags,
criteria) and writes a Markdown report: JSON schema compliance, gap to
expectations, latency, tokens/s. It only uses a throw-away database and **never
downloads a model**: a missing model is reported and skipped.

```bash
ollama pull qwen3.5:9b
ollama pull hf.co/<org>/<repo>:Q4_K_M   # any Hugging Face GGUF

cd backend
.venv/bin/python scripts/banc_pythia.py \
    --modeles qwen3:8b,qwen3.5:9b --sortie rapport.md

# openai_compatible server (e.g. llama-server already running on port 8080)
.venv/bin/python scripts/banc_pythia.py --moteur openai_compatible \
    --url http://127.0.0.1:8080/v1 --modeles my-model
```

## Laya judge (KRINOS)

A second, “System 1” opinion on every tender, **100% local**. Open-source model
(Apache 2.0) from Convai Innovations, multilingual checkpoint (mmBERT-base), run
**inside the backend process through ONNX Runtime** with the `tokenizers` package:
no PyTorch, no server, no key, no budget.

- **Consented download**: Settings › Autonomous pipeline › “Laya judge”. A
  confirmed click downloads `onnx-community/laya-multilingual-ONNX` (pinned
  revision, ~0.7 GB fp16, ~1.3 GB fp32) into `<HERMES data folder>/modeles/laya`;
  each file's SHA-256 is verified. Nothing is downloaded at startup. Without the
  model, Laya stays off and PYTHIA's analysis runs alone.
- **Questions**: relevance, the 5 KRINOS dimensions (0-4 scores), manipulation.
  Every portal is judged, private ones included. Routing thresholds, composite
  score, calibration and the “needs review” flag never promote a tender
  automatically.
- **Context**: 1024 tokens (training value, `HERMES_LAYA_MAX_TOKENS`, max 8192):
  notice + business profile + tender file excerpt (60% head, 40% tail, suspicious
  passages).
- **Calibration temperature** (0.5 to 5, default 1): the model ships
  over-confident; T > 1 flattens probabilities.
- **Benchmark** (outside CI, needs the model): `backend/scripts/banc_laya.py`;
  results and limits in [`docs/laya.md`](docs/laya.md).

## Features

- **User and business profiles** set at first launch and in Settings, used locally
  by KRINOS (scoring) and HERMION (drafting).
- **Real ARGOS collection**: BOAMP through the public DILA API and TED Europa
  through the public v3 API, stored in SQLite/MNEMOSYNE; incremental collection
  with pagination, network retry/backoff, automatic expiry of past-deadline
  tenders, open notices only.
- **ARGOS filtering**: include/exclude keywords (AI suggestions through PYTHIA)
  and server-side advanced filters (CPV, country, BOAMP descriptors and
  departments, contract type, dates). Irrelevant tenders are rejected before
  insertion and remain viewable under “Filtered out”.
- **KRINOS extraction**: PDF (tables as Markdown, OCR of scanned pages with
  RapidOCR — bundled models), DOCX, XLSX (zip-bomb safe), HTML; SHA-256 checked
  before every read.
- **KRINOS AI analysis (PYTHIA)**: summary, 0-100 score, business tags and award
  criteria; per-dimension scores with configurable weights and “Recalculate
  score” without re-running PYTHIA; prompt-injection detection, local
  anti-manipulation judge and “needs review” flag.
- **DECP competition panel**: recurring winners, median amount and trend from
  data.gouv.fr open data.
- **HERMION drafting**: multi-section markdown response (outline, then section by
  section), user workflow derived by AI from past responses, versioning
  (`v1`, `v2`, …) and mandatory human approval.
- **Responses tab**: live list by status, markdown preview, inline editing,
  approve / request changes / reject, local PDF export (fpdf2) to a destination
  chosen in a native dialog.
- **Autonomous pipeline**: after each ARGOS cycle, KRINOS analyses and the
  best-scored tenders go to HERMION — drafts always stop at “pending” for a human.
- **Desktop integration**: native notifications, menu bar / system tray icon
  (pause or run the watch, quit), keyboard shortcuts (Ctrl/Cmd+1…5, Ctrl/Cmd+K).
- **Agent log** tab and in-app notification centre.
